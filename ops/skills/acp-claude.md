# Skill: acp-claude

> dispatched(GitHub webhook 트리거) 코딩 작업을 **Claude Code(ACP)** 에 위임해 실행한다.
> OpenClaw = 지휘·중계, Claude Code(ACP) = 실행기. **OpenClaw 전용 스킬** (`.codex`/`.claude` 어댑터 없음 —
> Claude 런타임은 자기가 실행기라 무의미, Codex 는 대상 아님).
> 판단 기준·트리거/승인 규약은 palab-platform 을 참조한다 (여기 복제하지 않는다).
> spec: palab-platform `docs/operations/event-driven-trigger-design.md` (트리거·승인 경계).

## 언제 실행

- `dispatch:<봇>` 라벨로 깨어난 **코딩/구현/변경** 작업. 조회·요약만이면 대상 아님(직접 처리).

## 입력

- dispatched 카드: 이슈 title / 본문 / AC / **기존 댓글 전체** / `html_url`. 대상 repo(+브랜치).
- **전제**: OpenClaw 에 `gh` 가 인증돼 있어야 한다(repo 준비용). 작업 repo 는 acp 워크스페이스 아래
  **`prj/<repo>`** 에 둔다 (예: `/root/.openclaw/workspace-claude/prj/<repo>`).

## 절차

0. **카드 상태부터 파악 — 본문 + 전체 댓글을 읽고 대조한다.** 깨움 메시지는 제목·링크뿐이라
   그것만 보고 착수하면 이미 한 일을 다시 하거나 상태를 틀리게 보고한다("완료했다 / 아직 남았다" 핑퐁의 원인).
   ```bash
   gh issue view <번호> -R <owner>/<repo> --comments
   ```
   - **이미 된 것**(직전 PR 링크·"완료" 댓글·머지된 슬라이스)과 **남은 것**(AC 미충족 항목·리뷰 지적)을 가른다.
   - 여러 슬라이스로 나뉜 카드면 **이번에 할 슬라이스만** 집는다. 앞 슬라이스를 다시 만들지 않는다.
   - 진행 상태의 정본은 **본문 AC 체크박스**다. 댓글과 본문 체크박스가 어긋나면 본문을 신뢰하고, 마무리에서 갱신한다.

1. **대상 repo 준비** — 작업 경로는 `<워크스페이스>/prj/<repo>`.
   - 없으면 `gh repo clone <owner>/<repo> <워크스페이스>/prj/<repo>`
   - 있으면 `git -C <경로> fetch --prune` 후 기본 브랜치를 최신화.
   - 작업은 **새 브랜치**에서 한다(카드 번호 기반 권장, 예: `feat/<issue-number>-<slug>`).
2. **작업 프롬프트를 좁게 정리** — 3단계를 `--approve-all` 로 돌리므로 **실행 중 사람 승인 게이트가 없다.
   따라서 여기 적은 범위가 곧 안전 경계다.** 매번 아래를 구체적으로 명시한다(넓게 열어두지 않는다):
   - **변경 가능 파일** — 경로를 콕 집어 적는다 (예: `docs/acp-verify.md` 이 파일 하나만)
   - **금지 경로** — 예: `.github/`, `ops/`, 시크릿·설정 파일, **repo 밖 전부**
   - **브랜치 규칙** — 예: `feat/<issue-number>-<slug>` 새 브랜치에서만, **`main` 직접 커밋/푸시 금지**
   - **커밋/푸시 여부** — 커밋까지인지 push 까지인지 명확히
   - AC(완료 기준) + 기대 산출물, 그리고 1의 repo 경로·브랜치
   - **Android repo 면 로컬 빌드/에뮬 실행을 위임 범위에 넣지 않는다** — 코드 변경 + push 까지만.
     빌드 검증은 `## Android` 의 CI 루프로 대신한다.
3. **Claude Code 에 위임** — 기본 경로는 **`direct acpx claude`** 를 쓴다.
   (ACP 런타임 세션은 채널 컨텍스트에서 스레드 바인딩이 실패하는 경우가 있어, direct 경로를 기본 우회로 둔다.)
   실행 옵션은 **고정**한다:
   ```
   --approve-all --non-interactive-permissions fail --cwd <1의 repo 경로>
   ```
   - `--approve-all` — 대화형 승인이 불가한 환경이라 전부 승인. **그래서 2단계 범위 명시가 유일한 방어선.**
   - `--non-interactive-permissions fail` — 승인 프롬프트가 필요하면 **매달리지 말고 실패**(무한 대기 방지).
   - `--cwd <repo 경로>` — 1단계에서 준비한 디렉터리로 고정(다른 경로에서 돌지 않게).
4. **결과 회수·보고** — 변경 요약 + AC 대비 검증 결과 + 남은 위험/다음 액션을 카드/스레드에
   사람이 읽게 정리한다. 위임 응답을 그대로 붙여넣지 않는다.
5. **마무리 (closeout) — 브랜치에서 멈추지 않는다.** 커밋만 남기고 끝내면 그 작업은 아무 데도
   도착하지 않는다. 다음까지 해야 한 건이 끝난 것이다:
   - **push + PR 생성.** 본문에 카드 번호를 `Refs #N` 으로 건다 — **`Closes #N` 은 쓰지 않는다**(카드는 봇이
     아니라 Neo 가 검증 후 닫는다). AC 를 일부만 했으면 **남은 항목**도 적는다.
   - 카드에 **PR 링크**를 댓글로 남긴다. (PR 의 상호참조만으로는 카드의 `updated_at` 이 갱신되지 않아
     정체 카드로 잡힌다.)
   - 위험 작업이라 머지를 사람이 해야 하면 **draft PR** 로 올리고 무엇을 봐야 하는지 적는다.
   - 본문 AC 체크박스를 이번 슬라이스 결과로 갱신한다(진행 상태 정본, 절차 0 참조).
   - **슬라이스를 끝냈으면 카드에 `awaiting-review` 라벨을 붙인다** → 라우터가 finisher 의 claim 을 회수하고
     요청자(Neo)를 재기동해 검증(verify-ac)으로 잇는다(완료→리뷰 핸드오프, design §5).
     ```bash
     gh issue edit <번호> -R <owner>/<repo> --add-label awaiting-review
     ```
   - **봇이 스스로 카드를 닫지 않는다.** 완료 판정·카드 닫기는 **Neo** 가 verify-ac 후 `github-project-closeout`
     계약대로 한다. gated·Human required 카드는 라우터가 자동 진행 대신 사람에게 넘긴다.
   - **Android repo 면 여기서 로컬 빌드로 끝내지 말고 `## Android` 절차를 탄다.**

   **마무리 명령은 인용에 강하게 짠다 (조용한 실패·가짜 에러 방지).** 여러 줄 한글·마크다운 본문을
   `--body "..."` 나 heredoc 으로 인라인하면 특수문자(`-`, `/`, 백틱, 줄바꿈)가 셸 인용을 깨서
   `Bash failed: … EOF` 로 끝난다 — 작업은 성공했는데 실패처럼 보여 사람이 헛되이 개입하게 된다.
   - **본문은 항상 파일로.** 임시 파일에 쓰고 `-F`/`--body-file` 로 넘긴다. 인라인 heredoc 금지.
     ```bash
     printf '%s\n' "$COMMENT_BODY" > /tmp/acp-comment.md
     gh issue comment <번호> -R <owner>/<repo> -F /tmp/acp-comment.md
     gh pr create -R <owner>/<repo> --title "<제목>" -F /tmp/acp-pr.md ...
     ```
   - **마무리 단계는 실패를 삼키지 않는다.** 댓글/PR 명령이 실패하면 **1회 재시도**, 그래도 실패하면
     원시 bash 에러를 그대로 뱉지 말고 **무엇이 어디까지 됐는지**를 스레드에 구조화해 보고한다
     (예: "PR #14 생성됨 · 카드 댓글 실패(사유 X) → 사람이 댓글 확인 요망"). 성공한 작업이 규약 위반처럼
     보이지 않게 한다. 보고 문장은 **§보고·에러 표면** 규약을 따른다.

## Android (빌드는 CI, 동작은 사람)

Android repo(PaClaw · BookPlay-Pro · HowMuchToday · GCPNewsAndroid)는 **봇 노드에서 로컬 빌드하지 않는다.** 이유가 실측됐다 —
`./gradlew` 로 로컬 빌드하면 `google-services.json` 부재로 막힌다. 그 시크릿(키스토어 포함)은 **CI 에만
있고 봇 노드엔 없다.** 그러니 빌드는 시크릿이 있는 CI(GitHub Actions)에 맡기고, 봇은 **결과만 수거**한다.
**앱이 실제로 동작하는지(런타임/기능)는 자동화할 수 없으므로 사람이 확인**한다 — 봇의 검증 상한은
"CI green(컴파일 + 유닛테스트)"까지다.

절차 2의 위임 프롬프트에 **로컬 빌드/에뮬 실행을 넣지 않는다.** 코드 변경 + push 까지만 위임하고,
빌드 검증은 아래 CI 루프로 대신한다.

**흐름:**

```
코드 변경 → push (로컬 빌드 X) → CI(android-verify) 트리거 → 결과 대기
   ├ 실패(코드)        → 원인 파악 → 수정 → 재push → CI 재트리거   (green 될 때까지 루프)
   ├ 실패(시크릿/인프라) → 사람에게 보고. 봇은 시크릿을 건드리지 않는다.
   └ green            → "사람 확인 핸드오프" 작성 → 사람에게 통보 → 자동 진행 정지
```

1. **push → CI 트리거.** PR 검증 레인(`android-verify`, `pull_request`→main)이 `assembleDebug` +
   `testDebugUnitTest`(+lint)를 돌린다. google-services.json 은 CI 가 시크릿에서 복원한다.
2. **결과 수거.**
   ```bash
   gh run list -R <owner>/<repo> --branch <브랜치> -L 1 --json databaseId,status,conclusion,url
   gh run watch <run-id> -R <owner>/<repo> --exit-status   # 제한된 대기; 오래 걸리면 run URL 만 남기고 후속 확인
   ```
3. **실패 triage.**
   - **코드 원인**(컴파일·유닛테스트) → 로그를 보고 수정 → 재push → CI 재트리거. **green 될 때까지 반복**한다.
     단 무한 반복을 막기 위해 **같은 카드에서 몇 홉을 돌았는지 세고**, 진전 없이 반복되면 사람에게 올린다.
   - **시크릿/인프라 원인**(google-services 시크릿 미설정·quota·러너) → **사람에게 보고**하고 멈춘다.
     봇은 시크릿을 만들거나 바꾸지 않는다.
4. **green → 사람 확인 핸드오프.** 이게 이 카드의 종착점이다(동작 검증은 사람 몫). 아래 필드를 **본문 파일로
   써서**(§마무리의 `-F` 규칙) 카드에 댓글로 남기고, 카드에 `Human required` 를 표시해 **자동 진행을 멈춘다.**
   그 뒤 필요한 봇(Neo 종합)을 거쳐 사람에게 Discord 로 알린다.

   **사람 확인 핸드오프 — 필수 필드:**
   - **repo · 카드 #N · PR #M · 브랜치**
   - **어떤 작업이 수정됐나** — 이번 변경 슬라이스([1/3] 등) + 무엇을 왜 바꿨는지 요약
   - **CI 증거** — `android-verify` run URL(green) + APK 아티팩트 링크(있으면)
   - **사람이 확인할 것** — 이 변경으로 사람이 눈으로/손으로 봐야 하는 포인트
   - **테스트 필요 시나리오** — 단계 → 기대 결과, 대상 기기/에뮬(예: "R8 minify 릴리즈 빌드 설치 후
     첫 실행·핵심 화면 크래시 없음", "allowBackup=false 적용 후 재설치 시 데이터 초기화 확인")
   - **남은 위험 · 다음 액션**

   확인 사항과 테스트 시나리오는 **AC 와 실제 변경에서 봇이 도출**한다. "빌드됐습니다"로 끝내지 않는다 —
   사람이 무엇을 봐야 하는지까지 적어야 한 건이 넘어간 것이다.

## 보고·에러 표면 (사람이 읽는 글)

봇이 스레드·카드에 내보내는 글은 **사람이 읽는 글**이다. acp·bash·도구가 뱉은 원시 에러
(`Bash failed: … EOF`, 스택 트레이스, exit code, `~/.openclaw-…` 같은 내부 경로)를 **그대로 붙이지 않는다.**
무슨 일이 났고 **사람이 무엇을 하면 되는지**를 쉬운 한글로 옮긴다.

상황을 세 갈래로 나눠 판단한다:

- **작업은 됐고 부가 단계만 실패** (예: 커밋·PR 은 됐는데 카드 댓글만 실패, 또는 성공 뒤 도구 명령 하나가 헛돎)
  → **성공을 먼저 알리고** 남은 조치 한 가지만 덧붙인다. 실패처럼 보이게 하지 않는다.
  - 예: 마지막에 `Bash failed: … EOF` 가 떴지만 PR·댓글이 실제로 올라간 경우
    → "작업과 PR·댓글까지 정상 반영됐어요. 마지막 도구 명령 하나가 헛돌았을 뿐 결과엔 영향이 없습니다. 따로 하실 일은 없어요."
- **작업 자체가 막힘** → 원인을 한 줄로 옮기고 **다음에 할 일을 명령형 한 문장**으로 적는다.
  - 예(시크릿 부재): "CI 빌드가 google-services 설정이 없어 멈췄어요. 리포 Secrets 에 `GOOGLE_SERVICES_JSON_BASE64` 를 넣어 주세요." (봇은 시크릿을 직접 만들지 않는다)
  - 예(원인 불명): "OO 단계에서 멈췄는데 원인이 분명치 않아요. 확인이 필요합니다." — 원인을 지어내지 않는다.
- **정보 수준** (성공 로그, 진행 메시지, 무해한 경고) → **보여주지 않는다.** 필요하면 "정상 완료" 한 줄로 끝낸다.

규칙:
- 원시 로그·스택·내부 경로는 기본적으로 감춘다. 진단에 꼭 필요하면 보고 **맨 끝에 짧게** 참고로만 붙인다(본문에 도배하지 않는다).
- 사람이 할 행동은 늘 **명령형 한 문장**으로. 번역투·불필요한 영어를 쓰지 않는다 (palab-platform ko-writing-style).
- 원인을 모르면 추정하지 말고 "확인 필요"로 남긴다.

## 출력

- 변경 요약(파일/커밋) + **PR 링크** + AC 대비 pass/fail + kanban/카드 갱신 후보. (모든 보고는 §보고·에러 표면 규약을 따른다)

- 변경 요약(파일/커밋) + **PR 링크** + AC 대비 pass/fail + kanban/카드 갱신 후보.
- Android: **CI run URL(green) + 사람 확인 핸드오프**(확인 사항·테스트 시나리오 포함). "동작 확인은 사람" 명시.
- 위임 실패·범위 이탈 시: 무엇이 막혔는지 + 사람 확인 요청.

## 흔한 실패 (2026-07-23 실측)

dispatch 로 깨어난 카드 10건에서 봇이 브랜치에 커밋하고 카드에 "완료" 댓글까지 남긴 뒤 **PR 을 올리지
않고 멈췄다.** 작업은 main 에 도달하지 못한 채 하루가 지났고, 카드도 닫히지 않아 라우터의 정체(dead-letter)
감지에 11건이 한꺼번에 잡혔다. **"커밋했다" 는 완료가 아니다.** 5단계까지 끝내야 한 건이 끝난 것이다.

## 가드레일

- OpenClaw = 지휘·중계, **Claude Code(ACP) = 실행기.** 역할을 섞지 않는다.
- **`--approve-all` 이므로 실행 중 사람 승인 게이트가 없다.** 안전 경계는 **2단계 프롬프트에 적은 범위**뿐이다.
  변경 가능 파일·금지 경로·브랜치·푸시 여부를 매번 좁게 적는다. "알아서 해줘" 식으로 열어두지 않는다.
- 위험 작업(배포·시크릿·외부 전송·비가역)은 **애초에 위임 범위에 넣지 않는다.** 필요하면 사람 승인을 먼저 받는다
  (라우터 `gated` 게이트로 카드 단계에서 거르는 것이 1차 방어).
- 위임이 실패/불명확하면 **사람에게 보고하고 임의 진행하지 않는다.**
- 기존 클론의 워킹트리가 더럽거나(이전 작업 잔재) 충돌하면 **`reset --hard`·강제 정리 금지** —
  상태를 보고하고 사람 판단을 받는다(비가역 손실 방지).
- clone/최신화는 `gh`/`git` 로 하되, 대상 repo 외 경로는 건드리지 않는다.
